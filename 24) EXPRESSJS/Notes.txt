EXPRESS ROUTING VS REACT ROUTER

The main difference is where the routing takes place.

Express routing works on the server side:

app.get("/users", (req, res) => {
  res.send("Users");
});

app.post("/users", (req, res) => {
  // Create a new user
});

Every request is sent to the server. Express can:

- Handle HTTP methods such as GET, POST, PUT, and DELETE
- Communicate with a database
- Perform authentication and authorization
- Return HTML, JSON, files, or status codes
- Define backend and API routes

React Router works on the client side, inside the browser:

<Routes>
  <Route path="/" element={<Home />} />
  <Route path="/users" element={<Users />} />
</Routes>

React Router can:

- Decide which React component should be displayed for a URL
- Change the visible page without requesting a completely new HTML document
- Manage navigation inside a Single-Page Application (SPA)

React Router does not directly handle HTTP GET or POST requests, communicate
with a database, or replace a backend server.

They are commonly used together:

1. React Router displays the <Users /> component for the /users URL.
2. The React application sends a GET request to /api/users.
3. Express receives that request and gets the users from the database.
4. Express returns the data as JSON, and React displays it.

When a user submits a form, the flow may look like this:

React form --> POST /api/users --> Express --> Database

In short:

React Router answers: "Which screen should the user see?"
Express routing answers: "How should the server respond to this HTTP request?"

They are not alternatives to each other. In a full-stack React application,
React Router usually manages frontend navigation, while Express manages backend
requests and API endpoints.

Important: If the browser refreshes a React Router URL such as /users, the
request first reaches the server. The server must therefore be configured to
return the React application's index.html file for frontend routes.


HTTP REQUEST 

1. GET --> Requesting Resource 
2. POST --> Sending Resource 
3. PUT --> Updates the whole resource
4. PATCH --> (patchs up) updates determined areas only
5. DELETE --> Delete resources (from client to server side)


ENDPOINTS

URI, URL, path, and endpoint are related, but they do not mean exactly the same thing.

URI (Uniform Resource Identifier)

A URI is a general identifier for a resource. It tells us which resource we are
referring to. URL is one type of URI.

Example URI:

https://example.com/about

URL (Uniform Resource Locator)

A URL identifies a resource and tells us where it is located and how to access it.

Example URL:

https://example.com/about

In this URL:

- https is the protocol.
- example.com is the host.
- /about is the path.

Every URL is a URI, but not every URI is necessarily a URL.

Path

A path identifies a location inside an application or website.

Example path:

/about

In Express, this path can be used to define a route:

app.get("/about", (req, res) => {
  res.send("About Page!");
});

Endpoint

An endpoint is a location where a server receives a request. In an HTTP API, an
endpoint is commonly described using an HTTP method and a path or full URL.

Example endpoint:

GET /about

app.get("/about", (req, res) => {
  res.send("About Page!");
});

In this example:

- GET is the HTTP method.
- /about is the path.
- GET /about is the endpoint.
- https://example.com/about is the full URL.
- When the server receives this request, it responds with "About Page!".

The same path can be used by different endpoints because the HTTP methods are
different:

GET /users       --> Get the users
POST /users      --> Create a new user
DELETE /users/5  --> Delete the user with the ID 5

In short:

- URI identifies a resource.
- URL is a URI that also shows where the resource is and how to access it.
- Path is the part of the URL that comes after the host.
- Endpoint is where the server accepts a specific request, commonly represented
  by an HTTP method and a path.

If the server does not have a matching endpoint, Express may respond with:

Cannot GET /about

MIDDLEWARES

all available middlewares for express --> https://expressjs.com/en/resources/middleware

Middleware is a function that runs between receiving a request and sending a
response. It can process the request, modify the request or response objects,
end the request-response cycle, or pass control to the next function.

The general structure of an Express middleware function is:

function middleware(req, res, next) {
  // Process the request
  next(); // Continue to the next middleware or route handler
}

Example:

app.use((req, res, next) => {
  console.log(req.method, req.url);
  next();
});

app.get("/", (req, res) => {
  res.send("Home Page");
});

The request flow is:

Request --> Middleware --> Route Handler --> Response

Middleware is commonly used for:

- Logging requests
- Checking authentication and authorization
- Parsing incoming data, for example with express.json()
- Handling errors
- Adding information to the req or res object

If the middleware does not send a response, it must call next(). Otherwise, the
request will not continue to the next middleware or route handler and may remain
pending.

Before the backend ops, middlewares checking the incoming request's contents,
authentication or even verification. They decide that if incoming request suitable
or not for the operation

Useful especially for Auth based ops or DB related ops
for instance, system should be verify that the provided body is suitable to update the 
DB properly. (For instance, all the required fields are not empty or types are correct)



USAGE of bodyParser (external library) or express.urlencoded (internal) MIDDLEWARES

app.use(bodyParser.urlencoded({ extended: true }));
app.use(express.urlencoded({ extended: true }));

By the one of them, incoming POST data from Postman / Swagger or Form structure can be addressed inside of "req.body"

For instane, when we send from Postman

pet=cat
street=green

Express app can convert it to

{ pet: "cat", street: "green" }


MORGAN LOGGER FOR EXPRESS

An middleware that logging all the incoming requests and provided responses



NEXT() function

This is a function used within middleware that specifies under what conditions the middleware flow ends
and the general flow (backend operations such as GET/POST) continues.

CRITICAL POINT : flow can continue through the next middleware of route handler

USAGE EXAMPLE 1: (for the all routers)

function logger(req, res, next) {
  console.log("Request Method: ", req.method);
  console.log("Request URL: ", req.url);
  next();
}

app.use(logger); // necessary



USAGE EXAMPLE 2: (for specific router)

Caution: system will check all the defined middlewares according the order from left to right



app.use(express.urlencoded({ extended: true }));

function validateLogin(req, res, next) {
  const { email, password } = req.body;

  if (!email || !password) {
    return res.status(400).send("Email & password mandatory.");
  }

  next();
}

function checkPasswordLength(req, res, next) {
  if (req.body.password.length < 6) {
    return res.status(400).send("At least 6 chars.");
  }

  next();
}

function loginHandler(req, res) {
  res.send("logged in successfully");
}

app.post(
  "/login",
  validateLogin,
  checkPasswordLength,
  loginHandler
);
