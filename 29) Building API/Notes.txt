Handling GET Requests with Express.js
=====================================

1. Create a Basic Express Server
--------------------------------

import express from "express";

const app = express();
const port = 3000;

app.listen(port, () => {
  console.log(`Server is running at http://localhost:${port}`);
});


2. Receive a Path Parameter
---------------------------

A path parameter is a dynamic value included directly in the URL path.

Example request:

GET http://localhost:3000/users/42

Express route:

app.get("/users/:userId", (req, res) => {
  const { userId } = req.params;

  res.json({
    message: "Request received successfully",
    userId,
  });
});

For this request, req.params contains:

{
  userId: "42"
}


3. Receive Multiple Path Parameters
-----------------------------------

Example request:

GET http://localhost:3000/users/42/posts/7

Express route:

app.get("/users/:userId/posts/:postId", (req, res) => {
  const { userId, postId } = req.params;

  res.json({
    userId,
    postId,
  });
});


4. Receive Query Parameters
---------------------------

Query parameters appear after the question mark in a URL. Multiple query
parameters are separated with an ampersand.

Example request:

GET http://localhost:3000/search?keyword=javascript&page=2

Express route:

app.get("/search", (req, res) => {
  const { keyword, page } = req.query;

  res.json({
    keyword,
    page,
  });
});

For this request, req.query contains values similar to:

{
  keyword: "javascript",
  page: "2"
}

Values received through query parameters are normally strings. Convert a
value when the application needs a different data type.


5. Validate and Convert Query Parameters
----------------------------------------

In this example, keyword is required and page must be a positive integer.
If page is not provided, its default value is 1.

app.get("/search", (req, res) => {
  const { keyword } = req.query;
  const page = Number(req.query.page ?? 1);

  if (!keyword) {
    return res.status(400).json({
      error: "The keyword query parameter is required.",
    });
  }

  if (!Number.isInteger(page) || page < 1) {
    return res.status(400).json({
      error: "The page query parameter must be a positive integer.",
    });
  }

  res.json({
    keyword,
    page,
  });
});


6. Use Path and Query Parameters Together
-----------------------------------------

Example request:

GET http://localhost:3000/users/42/posts?sort=newest&limit=10

Express route:

app.get("/users/:userId/posts", (req, res) => {
  const { userId } = req.params;
  const { sort } = req.query;
  const limit = Number(req.query.limit ?? 10);

  res.json({
    userId,
    sort,
    limit,
  });
});


7. Handle an Optional Query Parameter
-------------------------------------

A query parameter may or may not be included in a request. A missing query
parameter has the value undefined.

These are both valid requests:

GET http://localhost:3000/search?keyword=javascript
GET http://localhost:3000/search?keyword=javascript&sort=newest

You can check whether sort was provided:

app.get("/search", (req, res) => {
  const { keyword, sort } = req.query;

  if (sort === undefined) {
    return res.json({
      keyword,
      message: "The sort parameter was not provided.",
    });
  }

  res.json({
    keyword,
    sort,
    message: "The sort parameter was provided.",
  });
});

You can also assign a default value:

const { sort = "newest" } = req.query;

There is an important difference between a missing value and an empty value:

GET /search
  req.query.sort is undefined.

GET /search?sort=
  req.query.sort is an empty string ("").

Use sort !== undefined when you only need to know whether the parameter was
provided. Using if (sort) treats both undefined and an empty string as false.


8. Property Access and Optional Chaining
----------------------------------------

Use req.query.key to read a query parameter:

const key = req.query.key;

The syntax req.query.key? is not valid JavaScript. Optional chaining uses ?.
and prevents an error if req.query is null or undefined:

const key = req.query?.key;

Express normally provides req.query, so req.query.key is generally enough.
To provide a fallback only when key is null or undefined, use ?? instead:

const key = req.query.key ?? "default-value";


9. Filter Many Possible Query Parameters
----------------------------------------

When an endpoint accepts many optional query parameters, define an allowlist.
Then keep only the supported parameters that were actually provided.

Example request:

GET http://localhost:3000/products?category=phone&minPrice=1000&brand=Apple

Express route:

app.get("/products", (req, res) => {
  const allowedQueries = [
    "keyword",
    "category",
    "sort",
    "page",
    "limit",
    "minPrice",
    "maxPrice",
    "brand",
    "color",
    "inStock",
  ];

  const receivedQueries = Object.fromEntries(
    Object.entries(req.query).filter(([key, value]) => {
      return allowedQueries.includes(key) && value !== "";
    })
  );

  res.json({ filters: receivedQueries });
});

For the example request, receivedQueries becomes:

{
  category: "phone",
  minPrice: "1000",
  brand: "Apple"
}

Parameters that were not sent are not included in the resulting object.


10. Convert Query Values to the Required Types
----------------------------------------------

Query values normally arrive as strings. Convert numbers and booleans before
using them in application logic or database filters.

if (receivedQueries.page !== undefined) {
  receivedQueries.page = Number(receivedQueries.page);
}

if (receivedQueries.limit !== undefined) {
  receivedQueries.limit = Number(receivedQueries.limit);
}

if (receivedQueries.minPrice !== undefined) {
  receivedQueries.minPrice = Number(receivedQueries.minPrice);
}

if (receivedQueries.maxPrice !== undefined) {
  receivedQueries.maxPrice = Number(receivedQueries.maxPrice);
}

if (receivedQueries.inStock !== undefined) {
  receivedQueries.inStock = receivedQueries.inStock === "true";
}

For this request:

GET /products?brand=Apple&minPrice=1000&inStock=true

The converted filters can look like this:

{
  brand: "Apple",
  minPrice: 1000,
  inStock: true
}


11. Reject Unsupported Query Parameters
---------------------------------------

Instead of silently removing unsupported parameters, an API can return a
400 Bad Request response and tell the client which parameters are invalid.

app.get("/products", (req, res) => {
  const allowedQueries = [
    "keyword",
    "category",
    "sort",
    "page",
    "limit",
    "minPrice",
    "maxPrice",
    "brand",
    "color",
    "inStock",
  ];

  const invalidQueries = Object.keys(req.query).filter(
    (key) => !allowedQueries.includes(key)
  );

  if (invalidQueries.length > 0) {
    return res.status(400).json({
      error: "Unsupported query parameters",
      invalidQueries,
    });
  }

  res.json({ filters: req.query });
});

For example, this request contains an unsupported parameter:

GET /products?brand=Apple&unknown=test

Response:

{
  "error": "Unsupported query parameters",
  "invalidQueries": ["unknown"]
}

Do not pass req.query directly into a database query without validation.
Using an allowlist prevents unexpected fields from reaching the database.


Summary
-------

/users/:userId
  Read the dynamic value with req.params.userId.

/search?keyword=javascript
  Read the query value with req.query.keyword.

/users/:userId/posts?sort=newest&limit=10
  Read userId from req.params and sort and limit from req.query.

Request body data
  Read it with req.body. Request bodies are commonly used with POST, PUT,
  and PATCH requests rather than GET requests.

Object.keys(req.query)
  Returns the names of the received query parameters.

Object.entries(req.query)
  Returns the received query parameter names and their values.

Object.fromEntries(...)
  Creates a new object from the filtered entries.

req.query.key ?? "default-value"
  Uses a default only when key is null or undefined.
