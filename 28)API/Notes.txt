
APPLICATION PROGRAM INTERFACE (API)

These are structures used for data exchange between programs with different or similar architectures. Kind of Brigde
One of the best things about it is that we don’t need to worry about the architecture or database structure of the applications we’re working with.
We just need to know how to send a request and what the response will be.

IOT architectures also can use API structures.




API TYPES
1. API TYPES ACCORDING TO SCTRUCTURE
2. API TYPES ACCORDING TO USAGE PURPOSE





API TYPES ACCORDING TO SCTRUCTURE

1. GraphQL (QUERYING LANGUAGE) --> It is an open-source data querying and processing language developed for APIs 
               It allows clients to request only the data they need—and nothing more—from the server.
               client receives only the data it needs.
               Scenario: Requesting only a user's name and email address

2. SOAP (PROTOCOL) --> (Simple Object Access Protocol) is an XML-based communication protocol that enables applications 
             written in different platforms and languages to securely exchange data over a network.
             In corporate systems that require strict rules and high security.
             Scenario: A bank sends a request to transfer funds to another bank in XML format.

3. REST API (ARCHITECTURE / USING HTTP PROTOCOL) --> It is an architecture that enables different software systems to communicate with each other 
                               securely over the Internet according to standard rules. It allows data (typically in JSON format) 
                               to be sent and received using the HTTP PROTOCOL. 
                               Common in simple web and mobile apps.
                               Scenario: Retrieve user number 5 as JSON using the GET /users/5 request.

4. gRPC (RPC FRAMEWORK) --> It is an open-source Remote Procedure Call (RPC) framework developed by Google that enables 
            high-performance, low-latency communication between different programming languages.
            For fast communication between microservices.
            Scenario: Microservices quickly querying inventory information.






API TYPES ACCORDING TO USAGE PURPOSE

1. Public/Open API --> These are APIs that are available to everyone (including external developers) 
                        over the Internet and are typically accessible via authentication
                        Example: A weather application retrieves Istanbul’s current temperature from a weather API

2. Private/Internal API --> These are APIs that are used solely for data sharing within a company’s or organization’s 
                            internal departments and systems and are not accessible externally
                            Example: A company’s internal application retrieves employee leave information from its database


3. Partner API --> This is a type of API provided to authorized individuals for the purpose of securely 
                    exchanging data between the systems of companies that have specific business partners
                    An e-commerce platform checks delivery information through its shipping partner’s API

4. Composite API --> These are APIs that combine multiple APIs or data sources into a single call to meet 
                    complex system requirements
                    Example: A single API request checks inventory, processes the payment, and creates a shipment.






AUTHENTICATION vs. AUTHORIZATION

Authentication: Answers the question “Who are you?” It verifies the user’s identity.
Example: Logging in with a username and password.

Authorization: Answers the question “What are you allowed to do?” It checks the authenticated user’s permissions.
Example: Only an admin can delete another user’s account.

Authentication verifies identity; authorization verifies permissions.

Login → Authentication → Authorization → Resource

Real-life example: Using an ID card to enter a company building is authentication. 
Being allowed to enter only specific rooms is authorization.

RATE LIMITING

a technique used to control the number of requests a client can make to a server within a set time period.
Usually remaining rate limit can be seen inside the response's header.

Request tracking: The server identifies clients using an IP address, user ID, or API key.
Threshold comparison: It checks recent usage against the allowed maximum.
Rejection: If a client goes over the limit, the server blocks extra requests and sends back a "429 Too Many Requests" status code
