COMMONJS VS ES MODULES

CommonJS and ES Modules are two different systems for sharing code between
JavaScript files.

CommonJS

CommonJS is Node.js's traditional module system.

const fs = require("fs");
module.exports = myFunction;

- It uses require() and module.exports.
- Files can use the .cjs extension.
- It can be enabled with "type": "commonjs" in package.json.
- require() generally loads modules synchronously.
- It does not support top-level await.

ES Modules (ESM)

ES Modules are JavaScript's modern standard module system.

import { readFile } from "node:fs/promises";
export default myFunction;

- It uses import and export.
- Files can use the .mjs extension.
- To use ESM in .js files, add "type": "module" to package.json.
- It is supported by browsers and Node.js.
- It supports top-level await.
- It is generally preferred for modern projects.

ES Module example:

import { writeFile, readFile } from "node:fs/promises";

CommonJS equivalent:

const { writeFile, readFile } = require("node:fs/promises");

- PATH GENERATION

We can use 2 methods for it.

1. const filePath = new URL("./message.txt", import.meta.url);
// import.meta.url --> The path that the current script located.
// "./message.txt" --> The target URL
// new URL GENERATES the object that include target path info

we can also generate the URL path more dynamically
const targetPathQR = new URL(`./QRCODES/${fileName}`, import.meta.url);

2. import path from "node:path";
const filePath = path.join("data", "users", "message.txt");

// Output --> data/users/message.txt


More Example

import { dirname } from "path";
import { fileURLToPath } from "url";

// import.meta.url --> current file path
// fileURLToPath(import.meta.url) --> full path according to operating system (EXPRESSJS/Middleware/index1.js)
// dirname(fileURLToPath(import.meta.url)) --> main folder name that include current file. (EXPRESSJS/Middleware)
const __dirname = dirname(fileURLToPath(import.meta.url));


res.sendFile(__dirname + "/public/index.html"); (EXPRESSJS/Middleware/public/index.html)

- JSON OPS

*** the JSON object cannot be used inside the JS file directly such JS object. Because they are actually
acts like STRING so before use we need to convert them into JS objects

*** While recording the JS objects as JSON objects, we need to convert them as STRINGIFY objects.

latestUrlObj = JSON.parse(data);
// converts the json object to js object.

const updatedObj = JSON.stringify({ ...latestUrlObj, ...obj }, null, 2);
// JSON.stringify generates json file from js object
// 1) If they have common keys, the value of the second object will be accepted.
// 2) null --> there wont be any filter or special function while merging
// 3) 2 --> indent value for more readible files

- DYNAMIC OBJECT NAMING

Normally we can define a key such below

const obj = {fileName: "abc"};

// Output --> { fileName: "https://google.com" }

we can create more dynamic structure for key definition

const fileName = "hero.png";
const url = "https://google.com";

const createdObj = {
  [fileName]: url
};

// Output --> { "hero.png": "https://google.com" }

fileName --> Direct key name
[fileName] --> definition of fileName as key name
